# IECTR62380

Online calculation for IEC TR 62380. A browser calculator that estimates the failure rate (FIT) and MTBF of an electronic board from its parts list and mission profile, following the approach of IEC TR 62380:2004 (*Reliability data handbook – Universal model for reliability prediction of electronics components, PCBs and equipment*, formerly UTE C 80-810 / RDF 2000) as described in public sources. Part families those tables do not cover use the public-domain MIL-HDBK-217F models.

**Live page:** https://evan-rw.github.io/IECTR62380/

> **The coefficients are not taken from the standard.** The mission profiles are published excerpts of it; everything else was copied from one open-source project ([Kicad-Space-Reliability](https://github.com/Eliot-Abramo/Kicad-Space-Reliability)) and has not been checked against IEC TR 62380. Each table in [`assets/tables.js`](assets/tables.js) lists its sources and how well they support it. Treat results as rough estimates: they are not suitable as evidence for an ISO 26262 or IEC 61508 safety case. (Using a purchased copy of the standard is not an option: the IEC licence does not allow it in software.)

## What it does

- **Mission profile:** one row per phase of a typical year: board ambient temperature t<sub>ac</sub>, working-time ratio τ, annual thermal cycles n and amplitude ΔT. Includes the profiles of Tables 1–2 of the standard and the automotive *motor control* and *passenger compartment* profiles of Table 11, as reproduced in TI SLOA294A.
- **Parts, IEC TR 62380 approach:** integrated circuits (die + package + electrical overstress), diodes, transistors, ceramic/tantalum/aluminium capacitors, film and SMD resistors, inductors and transformers.
- **Parts, MIL-HDBK-217F (Notice 2 where it applies):** mechanical and solid-state relays, switches, connectors, IC sockets, plated-through-hole circuit boards, quartz crystals, fuses, incandescent lamps, optoelectronics (LEDs, optocouplers, photodetectors), capacitors of every style the handbook lists (film, paper, mica, glass, ceramic, tantalum, aluminium electrolytic, variable), resistors of every style (composition, film, power film, networks, wirewound, thermistors, potentiometers), and inductive devices (fixed and variable coils and chokes, and flyback, audio, pulse, power and RF transformers, with the hot-spot temperature estimated from a known rise, the handbook's microminiature-coil figures, or power loss with case area or weight). Netlist import routes film, mica and trimmer capacitors, wirewound resistors, potentiometers, thermistors, inductors, ferrite beads and transformers to these models. One board-wide setting picks the 217F operating environment (ground benign to cannon launch). 217F rates are per operating hour, so the calculator weights them by each working phase's time share; dormant phases add nothing, unlike the 62380 models. The two methods differ in age and assumptions, so a board that mixes them is an estimate of an estimate.
- **Parts with vendor data:** a manufacturer's FIT rescaled to your mission profile, either from one temperature with the Arrhenius law, or from an IEC 62380 FIT report (die and package FIT at a stated profile, as TI publishes per part) using the 62380 formulas from TI SLOA294A. This path uses no coefficient tables at all.
- **Other parts** can be entered with a known failure rate. A part's type can be changed at any time; its reference, quantity and netlist data stay.
- **Failure modes:** each part's calculation lists how its failures split between short, open and drift (MIL-HDBK-338B Table 7.8-1, from RAC FMD-91). Marking a block redundant pre-fills its critical share with the members' short-circuit probability, marked Guessed.
- **Netlist import:** load a KiCad netlist (Eeschema's default s-expression export, which also carries each part's fields, symbol and do-not-populate flag) or a Protel or Protel 2.0 netlist (Altium, gEDA/Lepton and other tools export these). Parts are typed from their designators (U, C, R, Q, D, L…); where the designator names no part kind (OSC1, ABRT_SW101), from the KiCad symbol, the footprint library and name (Crystal, Connector_Dsub, LED_SMD…) or the value. Identical parts are grouped into one line ("C1–C12, C15"); a dash names a range only between two designators with the same prefix, so an Altium channel's R1-2 or R1-A is one part, and zero padding (C08–C10) is kept; test points, mounting holes, fiducials and other hardware are skipped, and do-not-populate parts are left out and listed. The manufacturer's name is kept but not read for the part type ("Samsung Electro-Mechanics" is not an electrolytic). IPC-7351 footprint names (SOIC127P600X175-8N, QFN50P400X400X80-25N) give the pin count and body size. Package, pin count, capacitor dielectric, resistor rating and some part families are worked out from footprint names and values; these are marked **Guessed** with the reason until changed or confirmed (a confirmed guess keeps its reason on record). Everything a netlist cannot hold (power, thermal resistance, voltage stress, transistor count…) is marked **Missing**, and that part is left out of the board total until it is filled in. A grouped line can be split into one line per reference when its parts run at different conditions.
- **BOM import:** load a bill of materials as CSV (comma, tab or semicolon separated; exports from Altium, KiCad, OrCAD and distributor BOM tools). Columns are found by their usual names (Designator or Reference, Quantity, Manufacturer Part Number or MPN, Manufacturer, Description, Value or Comment, Footprint or Package), and rows marked DNP or not fitted are left out. On an empty board the BOM builds the parts list, reading distributor-style descriptions such as "CAP CER 0.1UF 50V X7R 0603" or "RES SMD 10K OHM 1% 1/10W 0603" for the part type, dielectric, chip size and rating. After a netlist, it adds part numbers, manufacturers and descriptions to the lines with the same designators and improves their guesses, splitting a line whose parts have different BOM rows; values you typed or confirmed are kept. Part numbers and manufacturers are shown on each part and exported in the CSV.
- **Surface-mount solder joints:** for surface-mount boards, a wear-out check following MIL-HDBK-217F Notice 2 section 16.2. Each candidate device gets a cycles-to-failure life from its size (centre to furthest joint), solder joint height, leads (leadless, J, gull wing) and body against the board substrate's expansion, under the temperature cycles of the mission profile (phases combined with Miner's rule) or the handbook's equipment and environment tables; the worst device, the weakest link, adds its rate averaged over the mission length to the board total. "Fill from chip parts" lists the board's chip capacitors and resistors by size code (0603, 1206, tantalum case codes…) with their half-length filled in; ICs such as QFN, BGA and QFP are added by hand, and the joint height is always entered rather than guessed, since the result depends strongly on it. The model was derived for tin-lead solder and excludes manufacturing defects, and IEC TR 62380 parts already include joint fatigue in their package terms, so a checkbox leaves it out of the total.
- **Electrolytic capacitor life:** a wear-out check for aluminium electrolytic capacitors, wet, polymer and hybrid, with the makers' own published life rules: wet and hybrid capacitors last twice as long for every 10 °C cooler, polymer ones ten times for every 20 °C (each rule published by three or more makers; Chemi-Con's slower polymer rule is an option), worked out at 40 °C or above and capped at 15 years. Ripple heating comes from the current ratio and the rise at rated ripple, or a measured rise; for wet parts it halves life every 5 °C (Chemi-Con's rule, the harshest published). Phases of the mission profile combine with Miner's rule. End of life is a drift limit (capacitance, ESR), so each line says whether drift is a failure in its circuit, or follows a board-wide default; where it is, the share worn out by the end of the mission, from Cornell Dubilier's published wear-out spread (normal, mean 1.2 × the life, deviation 0.1 ×), is added to that line's rate as an average over the mission. Wet aluminium lines are checked by themselves; the rated life and temperature ("2000H 105C") and the kind are guessed from imported descriptions. Polymer and hybrid parts import as lines with the maker's failure rate entered. The tests check the rules against the makers' printed tables and Rubycon's worked example.
- **Tantalum and ceramic capacitors, makers' models:** a tantalum part type with a choice of KEMET's FIT method for its polymer parts (MIL-HDBK-217F's chip-tantalum model with KEMET's voltage factor referenced to 0.8 and π_Q 0.707, checked against KEMET's printed mission-profile tables), NASA's conservative polymer values applied to the maker's own rate (exponential B = 7, 0.7 eV), Vishay's MnO₂ nomograph (recovered exactly from the chart's vector artwork) or KYOCERA AVX's catalogue model for its MnO₂, polymer and niobium oxide parts (voltage and temperature read from the catalogue's vector charts, series resistance from its printed table); they disagree by up to 1000 × at derated voltage, so the choice is per part. A ceramic part type turns a maker's qualification life test into a rate: the 60 % χ² bound on the failures seen, divided by the device-hours and the acceleration (V_test/V)^n and Arrhenius, with n = 3 and 1.0 eV for precious-metal electrodes and the values entered for base-metal ones. Ceramic chips 1210 and larger are flagged for flex cracking, which no model counts. Polymer tantalum and niobium oxide import into that part type, with the NOJ or NOS series taken from the part number. The tests reproduce all 40 cells of Knowles' published C0G and X7R FIT tables, Samsung's worked example, the readings printed with Vishay's chart, the worked example in AVX's catalogue, KEMET's mission-profile FIT tables and TDK's confidence-level table.
- **Circuit board:** the bare board's main wear-out, plated-hole and via barrel fatigue, with the IPC-TR-579 model as published in open papers (equations from Sharon, SMTA 2014; Engelmaier's copper fatigue equation and FR-4 and copper properties from Brillhart et al., IPC APEX 2002). Pick a laminate (standard FR-4, Isola 370HR, Arlon 85N polyimide, Rogers RO4350B, from their data sheets) or enter a custom one; the z-axis expansion is integrated across its Tg. Each hole size (drill and plating) gets a cycles-to-failure life; the assembly reflows use up part of it (Miner's rule) and the mission profile's thermal cycles the rest, and the weakest size adds its rate over the mission length to the board total, with a checkbox to leave it out. Plating ductility and strength, the quality index K_Q and strain distribution K_d are entered, not assumed, because the result depends strongly on them; a hole size predicted to crack during assembly is flagged. No published worked example with full inputs was found, so the tests check the equations by hand calculation and the solver against the fatigue equation.
- **Results:** board failure rate, MTBF, survival over the mission, and each part's share of the total. While any line is incomplete, the total is shown as a lower bound (≥) and MTBF and survival as upper bounds (≤). By default the total counts a failure of any listed part as a board failure, so parts wired in parallel still add up. A "Show the calculation" panel on every part lists each factor (π<sub>t</sub>, π<sub>n</sub>, π<sub>α</sub>, λ3, …) per phase. **Generate spreadsheet** downloads the same figures as an Excel workbook (.xlsx, values only): a summary with the board rate, MTBF, survival and warnings; one row per part line with its method, rate each and total, share, rate breakdown, status and failure modes; the calculation factors; the temperature and cycling factors per phase; every input marked set, guessed (with the reason) or missing; the mission profile; the reliability structure; and the solder-joint, plated-hole and capacitor-life checks where used.
- **Reliability structure:** a tree and a zoomable block diagram that edit the same nested structure. Every part starts in "Everything else, in series"; parts that back each other up go into a redundant (k-of-n) block, where you say how many must keep working and what share of their failures (shorts, say) breaks the block anyway. Blocks nest, so two series power paths can sit inside a 1-of-2 block. Select by click, Ctrl/Shift+click, a lasso on the diagram, or by typing references (C1–C8, Q1) into Find; group with P (parallel) or S (series), ungroup with U, split a line with L, and move by dragging or with M. Netlist import proposes blocks of parts of the same type wired pin for pin to the same nets, such as decoupling capacitors on one rail (values may differ) or paralleled MOSFETs, and blocks of alike strings in series between the same two nets, such as two LED strings; they count in series until accepted. The two ends of a resistor, capacitor or inductor may be swapped, a resistor array is compared element by element, and a diode or transistor facing the other way is not in the block. Pins on nets that reach no other part (KiCad's "unconnected-(…)" nets) are ignored. ICs, connectors and parts with no model are never proposed, and nor are parts whose designator is used twice, which the import reports. A redundant block has no constant failure rate, so the board figures become averages over the mission length: survival over the mission, the mission-average failure rate −ln R(T)/T, and the mean time to failure ∫R(t)dt. Boards saved with the earlier flat groups load as top-level blocks.
- Every table value can be overridden per part.
- Boards are saved in the browser and can be exported/imported as JSON, or exported as CSV.

Families of the standard not modelled yet (optocouplers, optoelectronics, relays, connectors, switches, PCBs, protection devices, batteries, fans, converters and others) are listed on the page; enter them as "Other part" in the meantime.

## How it is built

A static site with no build step: the calculator (`index.html`), a data sources page (`sources.html`) listing every table, source, model and licence, and ES modules in `assets/`.

| File | Contents |
| --- | --- |
| `assets/tables.js` | IEC TR 62380 coefficient tables, each with its sources and a `status` |
| `assets/models.js` | The IEC TR 62380 failure-rate models: pure functions, no DOM |
| `assets/tables217f.js` | MIL-HDBK-217F coefficient tables, each with its sources and a `status` |
| `assets/models217f.js` | The MIL-HDBK-217F part models |
| `assets/failuremodes.js` | Failure-mode distributions (MIL-HDBK-338B Table 7.8-1) and the part-type mapping |
| `assets/netlist.js` | KiCad and Protel netlist parsers, the rules that guess part details, and parallel-block proposals |
| `assets/report.js`, `assets/xlsx.js` | The spreadsheet export: the workbook's sheets, and a small .xlsx writer (stored zip, no library) |
| `assets/bom.js` | BOM (CSV) parser, column detection, building parts from a BOM and merging one into a board |
| `assets/smt.js` | Surface-mount solder-joint check (MIL-HDBK-217F 16.2): cycles to failure, weakest link, chip candidates |
| `assets/pth.js` | Circuit-board plated-hole fatigue (IPC-TR-579): barrel strain across Tg, cycles to failure, assembly damage, weakest hole size |
| `assets/tablesboard.js` | Laminate library, copper plating properties and the plated-hole model's sources |
| `assets/caplife.js` | Electrolytic capacitor life: makers' life rules, ripple heating, wear-out spread, guesses from descriptions |
| `assets/tablescaplife.js` | The capacitor life rules, limits and end-of-life criteria, with their sources |
| `assets/modelsmaker.js` | Tantalum and ceramic capacitors from the makers' models and life tests |
| `assets/tablesmaker.js` | The makers' tantalum curves, the ceramic life-test constants and the board-flex limits, with their sources |
| `assets/structure.js` | Nested series and k-of-n blocks: survival, mission-average rate, mean time to failure, and the editing operations |
| `assets/structure-ui.js` | The structure editor: tree, zoomable block diagram, side panel, drag and drop, keyboard |
| `assets/art/` | Small pixel-art accents (portal, flame, key, boot, chip, circuit board, inspector, arrows, flame square, bug), generated by `tools/pixel_art.py` |
| `assets/app.js` | The calculator page: state, rendering, import/export |
| `assets/sources.js` | The data sources page, rendered from the same data modules |
| `tests/` | `node:test` tests for the models, the netlist import, the reliability structure and page behaviour (jsdom); `validation*.test.mjs` check the 217F models against every printed table value and the structure maths against a Monte Carlo simulation |
| `THIRD_PARTY_NOTICES.md` | Licence notice for the copied coefficient values |

Run locally:

```sh
npm install        # only needed for the tests
npm test
npm run serve      # then open http://localhost:8000
```

ES modules do not load from `file://`, so open the page through a local server, not by double-clicking `index.html`.

## Publishing with GitHub Pages

In the repository on GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, branch `main`, folder `/ (root)`, then **Save**. The page appears at https://evan-rw.github.io/IECTR62380/ a minute or two later and updates on every push to `main`. The `.nojekyll` file makes Pages serve the files as they are.

## Improving the coefficient data

Each table in `assets/tables.js` has a `status`:

| Status | Meaning |
| --- | --- |
| `excerpt` | A published excerpt of the standard (the free preview, or a vendor note that reproduces a table) |
| `corroborated` | Two or more independent public sources give the same values |
| `single` | One source so far, not checked against the standard |
| `handbook` | A MIL-HDBK-217F table read from the handbook's own pages, with no second transcription to compare against |

To strengthen a table, find an independent public source that states the same values, such as a semiconductor vendor's functional-safety FIT report that lists its IEC 62380 parameters, or a paper that applies the model. Add it to `SOURCES`, list it on the table, and raise the status to `corroborated` once every row is covered. Correct any value the sources contradict, and run `npm test`.

Do not copy text, tables or figures from a purchased copy of the standard into this repository: the IEC licence for purchased copies does not allow it. `*.pdf` is in `.gitignore` as a backstop.
